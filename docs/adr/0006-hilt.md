# 0006: Dependency injection with Hilt

- **Status:** Accepted (2026-09-29, Sprint 1). Replaces Koin.
- **Context:** 2.0 is the final release, so bindings must be verified before the app ships. Koin resolves at runtime, so a missing binding only crashes on the device. Google's reference apps (architecture-samples, Now in Android) use Hilt.
- **Decision:**
  - Use Hilt (Dagger 2.60.1, KSP).
  - Apply the `wifilens.android.hilt` convention plugin to every Android module that owns bindings or ViewModels.
  - Each `:data` module and each core module has one `@Module @InstallIn(SingletonComponent)` (`@Binds`, `@Singleton`).
  - Use-cases get `@Inject constructor` in their pure-JVM domain modules through `javax.inject`. There's no Android dependency.
  - ViewModels are `@HiltViewModel`, and screens obtain them with `hiltViewModel()`.
  - Dispatchers, `ApplicationScope` and `Clock` come from qualifiers in `:core:common`, provided by `app/di/CommonModule`.
- **Consequences:**
  - The migration already caught a real wiring bug: `AnalyzeViewModel` relied on Kotlin default arguments that Koin used silently.
  - Build time goes up slightly (KSP).
  - detekt exempts `@Inject` constructors from `LongParameterList`.
  - Instrumented tests currently drive screens directly. A test that launches `MainActivity` must use `@HiltAndroidTest` and a Hilt test runner.
